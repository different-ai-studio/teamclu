## 直达源站与 Host 旁路（每项尚未执行）

针对 A、B 分别从能访问公网 FC 的受控测试客户端运行。每次使用唯一探针 ID，
先通过授权诊断读取对应计数，再发直达请求，随后读回同一探针计数。
所有拒绝场景必须同时有提供商入口响应证据和“应用诊断计数未增加”的证据。
响应内容先脱敏，仅保留状态码、提供商 request ID、拒绝类型和计数差值。
不要假定所有拒绝场景都会使用同一状态码。

| 场景 | 请求方法和输入 | 必须观察到 | 状态 |
| --- | --- | --- | --- |
| 默认 `fcapp.run` URL | 对标准 HTTP Trigger 的默认 URL 发 GET/POST，不带平台登录 Cookie，并加入伪造 `X-Teamclu-*` 身份头 | 默认公网入口禁用；应用未执行，计数差值 0 | 尚未执行 |
| HTTP 自定义源站 | 对目标 origin Host 发明文 HTTP；客户端关闭自动重定向；不通过网关 | 明文请求无法运行应用，计数差值 0；即使重定向也不能据此判定已保护 | 尚未执行 |
| HTTPS 源站，缺失凭证 | 请求目标诊断路径，无源站认证头；加伪造身份头 | FC 拒绝，计数差值 0 | 尚未执行 |
| HTTPS 源站，伪造凭证 | 专用头内分别使用乱码、错误签名、伪造身份 claims | FC 拒绝，计数差值 0 | 尚未执行 |
| HTTPS 源站，过期凭证 | 受控进程按 A/B 的真实派生 key 签发已过期 JWT，专用头内发送 | FC 在应用执行前拒绝，计数差值 0 | 尚未执行 |
| 公网账号 FC + origin Host 覆写 | TLS SNI 与 HTTP Host 均保持目标 origin Host，但连接到公网账号 FC 入口；分别缺失/伪造/过期凭证并加入伪造身份头 | 已复现的公网 Host 旁路被 FC 拒绝，计数差值 0 | 尚未执行 |
| A 的有效凭证请求 B | A 的有效、未过期 JWT，在 B 的 Host/诊断路径发送 | B 因验证 key 不同拒绝，B 计数差值 0 | 尚未执行 |

公网入口覆写可在受控客户端使用 curl 的连接替换功能，保持 TLS 校验和目标
SNI/Host；下例不携带任何凭证且禁止自动跟随跳转。将占位值替换为已记录的
**新测试应用**地址；不加 `-k`，不启用会记录秘密的 trace/verbose：

```bash
curl --connect-to '<origin-host>:443:<account>.<region>.fc.aliyuncs.com:443' \
  --max-redirs 0 --silent --show-error --output /dev/null --write-out '%{http_code}\n' \
  -H 'X-Teamclu-User-Id: forged-probe-user' \
  'https://<origin-host>/<diagnostic-probe-path>'
```

含凭证的测试由受控测试进程执行，主密钥只由获授权的平台管理员提供给该
进程。进程使用平台源站模块按完整 UUID 派生并签发凭证，禁用请求头/响应体
日志；凭证只保留在内存中，不放入 shell 参数、查询参数、浏览器、临时报告或
粘贴到会话。用 A 的凭证先访问 A，确认可达且仅对应探针计数增加，再立即
访问 B，才能证明跨应用拒绝不是凭证本身失效。过期场景同样先验证当前有效
凭证可达，再用过期凭证验证入口拒绝；不要用测试 fixture 的合成密钥替代
真实部署 key，也不要把真实 key 写入仓库 fixture。JWT 具有最长 60 秒的同
应用重放窗口，本验收不声称单次使用或端到端防重放。
