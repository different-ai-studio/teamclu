给 Agent 设限额前请三思

值守 Agent 和定时任务是无人值守运行的。给它设限额意味着额度用完时任务会在半夜静默失败，而没有人会看到那条错误。默认不限是刻意的。

规格

  • 发现一处 schema 与 UI 的错配：member_credit_quota 把 period 放在每个成员的行上，但这一屏按团队统一设置。成员各用各的周期会让「本周期已用」这一列不可比，报表也讲不通。建议把 period 提到团队级列；若保留现状，UI 必须强制向所有行写同一个值。§5.2
  • quota_exceeded 与 insufficient_credits 要分开呈现。 前者只拦一个人、解法是调限额；后者全员停、解法是充值。两者混成一句「额度不足」会把人引向错误的操作。§4.2
  • 把限额调到低于已用量时要提示。 该成员会立刻停到周期结束 —— 这是合法操作，但必须让所有者知道自己按下去会发生什么。
  • Agent actor 无显式限额行时跳过 quota 检查，只受团队余额约束。给 Agent 设限额要二次确认。§6.2.2
  • 「新成员默认」是附录 F 仅剩的两条未决之一。 现在按「不限」画；等有真实用量分布后再定，改的是数据不是结构。
  • 周期口径与用量报表共用同一套 CST 换算，不要各写一份。附录 A
  • 编辑限额的弹层记得传 container —— 设置页是模态 dialog，默认 portal 到 body 会永远打不开。§12.7
