# 资料库按需下载（惰性）设计

- **Date**: 2026-09-01
- **Status**: DESIGN — 待评审后实现
- **Scope**: `apps/daemon/`（`sync/oss/{engine,state}.rs`、新的按需拉取入口）、`apps/desktop/`、`packages/app/`（树的图标与下载入口）
- **Unfreezes**: `docs/adr/0008-knowledge-sync-p0-p1-scope.md` 的「按需下载（Smart Sync）」——**仅限 `documents/`**，见 §8
- **Related**: `docs/specs/2026-09-01-team-sync-two-roots-design.md`（两个固定根）、`docs/specs/2026-08-31-knowledge-path-acl-design.md`（目录级权限）

---

## 0. 一句话

`documents/` 的文件默认**不下载**，manifest 里有就在树里显示，点了才取。`knowledge/` 不变，仍然全量。

---

## 1. 为什么

省两样东西：**磁盘**（资料库会长到本地放不下）和**首次同步时间**（新成员不必等几个 G 下完才能开始用）。

**边界要先说清**：惰性只作用于资料库。知识库仍然全量，所以「新成员加入要等」这件事只解决了一半——知识库本身大的话，收益比预期小。

---

## 2. 前提：manifest 已经够用

`ManifestItem` 给的是 `path` / `version` / `content_hash` / `size` / `deleted` / `updated_at`（`fc_client.rs:23`）。**知道一个文件存在、多大、什么时候变的，本来就不需要下载它**——引擎只是目前无条件下载而已。

所以这个设计不需要新的服务端接口。要改的全在客户端。

---

## 3. 决策记录

### D1 — 未下载的文件在磁盘上「什么都没有」

不是零字节占位，不是 sidecar。路径在树里可见，是因为 UI 读的是清单，不是磁盘。

否掉零字节占位的理由不是省事，是**正确性**：引擎靠内容哈希判断变更，而一个被用户清空的文件和一个未下载的文件在磁盘上一模一样。用占位就等于让「有人在 Obsidian 里存了个空文件」和「还没下载」变成同一件事，而前者必须被同步、后者绝对不能。

**代价要认**：Finder、终端、agent 都看不到未下载的文件，只有我们自己的界面知道它存在。

### D2 — 未下载的路径不进 `state.files`

新开一张表（工作名 `known: HashMap<String, KnownFile>`），只存 manifest 已知但本机没有的条目：路径、version、content_hash、size。

**这是本设计最重要的一条。** 引擎判断「文件被本地删除」的依据是「在 `state.files` 里、不在扫描结果里」（`engine::locally_deleted_paths`），而「未下载」正好是这个形状。

评审时考虑过给 `FileState` 加一个 `materialized: bool` 并在墓碑计算里跳过——**否掉了**：那会让 `state.files` 里同时住着两种语义完全不同的条目，而这张表被十几处代码读。**任何一处忘了检查那个标志，就是一次团队级删除。**

分成两张表是用类型给出保证：**一个路径只要不在 `files` 里，它就永远不可能变成墓碑候选**，而这个保证不依赖任何调用方记得检查。

状态迁移只有两个方向，各自一处代码：

- 下载成功：`known` → `files`（同 `upsert` 已有路径）
- 手动释放：`files` → `known`（新增，见 D4）

### D3 — 反向操作只有手动释放

不做自动回收（LRU / 超预算）。

评审时选过「手动 + 自动」，后来收回。收回买到的：不用定预算、不用定排序、不用处理「后台删除撞上批量删除闸门」，而且**没有任何无人值守的删除**，D2 的重要性也随之从「承重」降回「重要」。

**代价**：省磁盘只解决了一半。不自动回收，占用仍会随着打开过的文件增长，只是慢；真要控制得靠人主动释放，而人不会主动。这是明知的取舍，不是疏漏。

### D4 — 释放的三条红线

手动释放同样适用，直接写死不给配置：

1. **dirty 的文件绝不释放。** 本地有未推送的改动，释放掉就是丢用户自己写的东西。
2. **释放不走墓碑路径。** 必须是独立代码路径，不经过 `locally_deleted_paths`，不产生 `delete_batch`。否则用户会看到「要删除 N 个文件吗」的确认框，而他什么都没删。
3. **只动 `documents/`。** 知识库是全量的，释放它等于把惰性偷偷扩大到没同意的范围。

措辞上「释放本地副本」必须和「删除」拉开距离——后者是团队级的。这跟权限设计里「停止同步 ≠ 撤回」是同一类问题：**两个动作在用户脑子里极易混淆，而后果完全不同。**

### D5 — agent 只看到已下载的

agent 通过 `team-documents` 符号链接用普通文件工具读，所以未下载的文件对它**根本不存在**。

否掉的两个替代：

- **agent 读不到就自动拉取**：一次 `grep` 会变成几个 G 的下载，而 agent 不知道自己在花什么代价。
- **给 agent 一个显式下载工具**：需要新接口，且 agent 未必会用。

**必须写进文档的后果**：同一个问题，agent 在不同人机器上会给出不同答案，因为各人下载的文件不同。

这跟当初把 RAG 排除在 documents 之外的理由是同一条，只是这次躲不掉：**只要 documents 既能被 agent 读、又是惰性的，这个不一致就存在**。它是选择惰性的代价，不是一个可以修的 bug。

### D6 — 图标只标两种状态

未下载 / 下载失败。

「已下载」是常态不标（标了整棵树全是图标）。**失败必须跟未下载分开**：用户的下一步动作完全不同，一个是「点一下就有」，另一个是「点了也没有，得先解决网络或权限」。

dirty 状态树里已有既有的同步状态色，不再叠一层。

### D7 — 离线直接报错，不排队

不做「加入队列，等有网自动下」。

那会制造一个用户看不见的待办：他点了、界面没反应、二十分钟后文件突然出现，而他早就不需要了。**惰性下载的全部价值在于「我要的时候它就在」**，延迟满足把这个价值抵消掉，还多一个要维护的状态。

## 4. 引擎的改动

### 4.1 pull 决策

今天：`needs_download = local.is_none() || item.version > local.synced_version`（`engine.rs`）。

改成：`documents/` 前缀的条目**不下载**，只写进 `known`；其余（`knowledge/`）不变。

已经 materialized 的 documents 文件继续按老规则更新——**一旦下载过，它就是普通的同步文件**，后续版本照常拉取。惰性只作用于「第一次」。

### 4.2 按需拉取

新增一个入口：给定一组路径，从 `known` 取 `content_hash`，走现有的 `download_batch`，落盘后 `known` → `files`。

复用现有下载路径意味着 ACL、可达性检查、配额全部自动适用——**未下载不等于无权限**，无权限的文件压根不在 manifest 里，连 `known` 都进不去。这两种状态在 UI 上也必须分得开：一个是「点了能有」，另一个是**它对你根本不存在**。

### 4.3 扫描

`scan_workspace_with` 不变——它只走磁盘，而未下载的文件不在磁盘上。这正是 D1 想要的：扫描器对惰性一无所知。

---

## 5. UI

- 树的行来自 **manifest ∪ 磁盘**，而不是只有磁盘。未下载的行带 D6 的图标。
- 点击一个未下载的文件 = 下载它，然后打开。
- 右键：文件和文件夹都提供「下载」；已下载的提供「释放本地副本」。
- 文件夹整体下载要有进度和取消——一个目录可能是几百个文件，没有取消的长任务是不可接受的。
- 释放的确认文案必须说明「服务器上的内容不受影响，随时可以重新下载」，把它和删除区分开。

---

## 6. 明确不做

- 自动回收（D3）
- 零字节占位（D1）
- agent 触发下载（D5）
- 离线队列（D7）
- `knowledge/` 的惰性 —— 全量是它的性质
- 块级 / CDC 同步 —— ADR-0008 的其它 freeze 条目**不受本设计影响**

---

## 7. 实施顺序

1. `state.rs`：新增 `known` 表 + 两个方向的迁移函数（**不含**任何墓碑逻辑）
2. `engine.rs`：pull 对 `documents/` 只登记不下载
3. 按需拉取入口 + HTTP 暴露
4. 手动释放（含 D4 三条红线）
5. UI：清单 ∪ 磁盘的树、图标、下载/释放入口、文件夹进度与取消

### 验收

- [ ] 一台机器上把资料库全部释放后，**下一次 tick 不产生任何墓碑**，其他成员的文件完好 ← 最重要的一条
- [ ] dirty 的文件拒绝释放
- [ ] 释放不触发批量删除闸门的确认框
- [ ] 释放只能作用于 `documents/`，对 `knowledge/` 的调用被拒
- [ ] 未下载的文件下载后，后续版本按普通同步文件更新
- [ ] 无权限的目录既不在树里、也不在 `known` 里（与「未下载」区分）
- [ ] 离线时点下载报错，不留下隐形队列
- [ ] agent 通过 `team-documents` 只看到已下载的文件（确认我们知道它会这样）

---

## 8. 与 ADR-0008 的关系

ADR-0008 的 freeze 清单里有「按需下载（Smart Sync）」。本设计**解冻它，但仅限 `documents/`**。

`knowledge/` 的按需下载**仍然冻结**，理由不是没做，是**不该做**：知识库的价值在于全员看到的是同一份东西，惰性会让 agent 与 RAG 的行为因人而异（D5 已经在 documents 上承认了这个代价，那是权衡；在 knowledge 上它是自毁）。

同批更新 0008 的清单，注明这条只对 documents 解冻。否则下一个读到 0008 的人会把整件事推回去，或者反过来顺手把 knowledge 也做了。

---

## 9. 风险

1. **D2 写错 = 团队级数据丢失。** 未下载的路径一旦漏进 `state.files`，第一次 push 就把它们当本地删除广播出去。验收第一条守的就是这个。
2. **D5 的不一致无法消除。** agent 在不同人机器上给不同答案，这是选择惰性的固有代价。要确保支持侧知道这个症状，别当 bug 查。
3. **「释放」被当成「删除」。** 措辞和位置必须把两者拉开；一次误解就是用户以为自己删掉了团队的文件。
4. **D3 的取舍会在几个月后显形。** 磁盘照样会满，只是慢。届时再谈自动回收，而不是现在顺手加。
