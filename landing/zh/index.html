共享的技能，和群聊一样的会话。

TeamClu 是一个工作台：你的同事和 AI agent 在同一个会话里一起干活。 技能发布一次，全队每个人的 agent 自动跟随——不用再各自去教一个私有的 bot。

agent 跑在你自己机器上

agent 是私人的。这对一个团队来说，形态就是错的。

我教会我的 agent 我们怎么发版。一个月后，同事教会他自己的 agent 同样的事， 稍微有点不一样。而真正干活的过程，发生在一个别人都看不见的聊天窗口里。

所以 TeamClu 把两件事从「私有」变成「共享」：agent 知道怎么做， 以及它们一起干活的那个会话。

全队共享的技能

技能是版本化的团队资产，不是一段躺在别人 dotfiles 里的提示词。

把技能带着结构化元数据和 changelog 发布到团队注册表， 全队每个人的 agent 会自动跟随新版本——后台对账循环负责这件事， MQTT 让它几乎即时。再也不用发那句「记得更新你的技能」。

本地改了共享技能，得到的是一个需要你处理的冲突，而不是一次静默覆盖。 谁发布了坏版本，点一下就能把上一个版本重新发成新的 latest。

发布权限
任何团队成员都可以。owner 是责任，不是权限。
版本历史
每个版本不可变，且带 changelog。
自动更新
已安装的团队技能自行跟随 latest_version。
本地改动
产生冲突，绝不静默覆盖。

会话就是群聊

不是一对一地跟 bot 聊天。同事和 agent 共用一条时间线、一个上下文。

把同事加进来，@ 某个人，看谁在线，把任意一条 agent 回复拉成独立线程。 agent 是参与者，不是服务端：它可以离线、可以被限权，也可以在对话中途换模型。

没被 @ 到的 agent 不会插嘴。这是设计，不是故障。

参与者
人和 agent 混排，在线状态用小圆点区分：人是绿点，agent 是珊瑚点。
@提及
被提及不等于有权限，不会因此把你拉进会话。
线程
任意一条 agent 回复都能开成独立线程。
逐个控制
可离线、可限权、可中途换模型。

值得先问清楚的问题

包括还没做的部分。

全队共享的是同一个上下文吗？
不是。技能、知识库、角色和 MCP 配置是团队资产，每个成员保留自己的 私有上下文。这个切分是刻意的：正是它让你能共享能力，而不必共享一切。
能让某个技能对部分同事保密吗？
目前不行。加密是一个团队一把密钥、全体共用——它防的是云厂商，不是同事。 按成员的可见性隔离还没做。
@ 一下就等于有权限了吗？
没有。在渠道里 @bot 的含义是「这条消息给 agent」， 不会把人拉进会话。
agent 到底跑在哪里？
跑在你自己机器上，由本地 amuxd 托管，不在我们的云里。 你可以从企业微信、飞书、Discord、KOOK、微信或邮件触达它们， 会话还是同一批。
有人发布了坏版本怎么办？
每个版本不可变且带 changelog，点一下就能把旧版本重新发成新的 latest。 你的本地改动不会被自动更新静默覆盖。
能当生产环境用吗？
现在是 v0.4.1 beta。拿去试、提 issue、接受粗糙的边角。 macOS 包未签名，Gatekeeper 会拦一下，README 里有 xattr -cr 的说明。
